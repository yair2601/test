# Priority RPA — שלב הסיור (Discovery)

כלים שרצים אצלך במחשב ועונים על השאלות שצריך לענות עליהן **לפני** שכותבים את
טוען ההזמנות: איך נראה האקסל באמת, ואיך נראה מסך ה-ORDERS שלך ב-Priority.

> **הכלים האלה לא כותבים ל-Priority.** הם לא לוחצים, לא מקלידים ולא שומרים.
> אתה מנווט בדפדפן ידנית, והם רק מסתכלים ומתעדים. זה מכוון: אין סביבת בדיקות,
> אז שום דבר אוטומטי לא נוגע בנתונים חיים.

```bat
cd priority-rpa
python -m venv .venv

pip install -r requirements.txt
```

בדיקה שהכל עובד, בלי להתחבר ל-Priority — רץ מול עמוד HTML מקומי שמדמה מסך:

```bat
python tests\smoke_test.py
```

אמור להדפיס `All checks passed.`

## 1. פרופיל האקסל — `inspect_excel.py`

רץ אופליין לגמרי. לא נוגע ב-Priority ולא ברשת.

```bat
python inspect_excel.py orders.xlsx
```

מדפיס וכותב `excel-profile.md` עם:

* באיזו שורה נמצאות הכותרות (מזהה לבד גם אם יש שורות רעש מעליה)
* כל עמודה: כמה מלאה, כמה ערכים שונים, **הטיפוס האמיתי** של התאים ודוגמאות
* המלכודות שמפילות טעינות: מספרים ששמורים כטקסט, אפסים מובילים
  (`0012345`), תאריכים שהם בעצם מחרוזות, רווחים בקצוות, ערכי float
* אילו עמודות מתאימות להיות עמודת האסמכתא

אחרי שבחרת אסמכתא:

```bat
python inspect_excel.py orders.xlsx --ref-column "אסמכתא"
```

מוסיף:

* כמה הזמנות ייווצרו, וכמה שורות בכל הזמנה (מינימום/מקסימום/ממוצע)
* האם השורות של הזמנה אחת רצופות בקובץ
* **אילו עמודות הן רמת כותרת** (קבועות בתוך הזמנה ⇒ ORDERS) **ואילו רמת שורה**
  (משתנות ⇒ ORDERITEMS) — זה עונה לבד על שאלת המיפוי
* **קונפליקטים**: אסמכתא אחת עם שני לקוחות שונים או שני תאריכים. אלה בדיוק
  המקרים שמפילים טעינה באמצע, ועדיף לגלות אותם עכשיו
* שלד מיפוי מוכן להדבקה ל-config

אם תרצה לשלוח לי את הדוח — הרץ עם `--anonymize`. זה מחליף ספרות ב-`9`
ואותיות ב-`A`/`א`, ושומר את **הצורה** של הערכים בלי התוכן:

```bat
python inspect_excel.py orders.xlsx --ref-column "אסמכתא" --anonymize
```

## 2. התחברות חד-פעמית — `login.py`

```bat
python login.py --url https://your-priority-host/...
```

נפתח דפדפן אמיתי. מתחבר בעצמך, עובר MFA, בוחר חברה אם צריך, **ואז מנווט למסך
ההזמנות** — ורק אז חוזר לטרמינל ולוחץ Enter.

נשמרים שני קבצים:

* `storage_state.json` — ה-session (עוגיות). **לא בגיט, לא לשלוח לאף אחד.**
* `session-info.json` — ה-URL שעליו עמדת ועץ ה-frames. זה ה-`orders_url` שלך.

אין סיסמאות בקוד, בקונפיג או בדיסק — רק העוגיות שהדפדפן ממילא מחזיק.

## 3. סיור במסך — `explore_priority.py`

```bat
python explore_priority.py
```

(לוקח את ה-URL מ-`session-info.json`; אפשר לעקוף עם `--url`.)

נפתח דפדפן עם ה-session השמור, ונפתחת שורת פקודה. **אתה** מנווט בדפדפן,
**היא** מתעדת.

| פקודה | מה היא עושה |
|---|---|
| `frames` | עץ ה-iframes. עונה על "באיזה frame יושב המסך" |
| `dump <תווית>` | צילום מלא של המסך הנוכחי לתיקייה |
| `snap` → פעולה ידנית → `diff` | מה **בדיוק** השתנה בגלל הלחיצה שלך |
| `pick` → לחיצות שלך → `stop` | סלקטורים מאומתים לכל מה שלחצת |
| `net on` / `net show` | אילו קריאות XHR המסך עושה |
| `url`, `help`, `quit` | |

### הסדר שאני ממליץ עליו

1. `frames` — ללמוד את מבנה ה-frames
2. `dump orders-empty` — צילום בסיס של מסך ההזמנות
3. `snap`, ואז ללחוץ **בעצמך** על "רשומה חדשה", ואז `diff`
   → רואים בדיוק אילו שדות הופיעו, איזה כפתור נדלק, אם נוספה שורה
4. `pick`, ואז ללחוץ בעצמך על: רשומה חדשה, שדה אסמכתא, שדה לקוח, שדה תאריך,
   המעבר לשורות, שדה מק"ט, כפתור שמירה. ואז `stop`
   → מקבלים סלקטור מאומת לכל אחד
5. `dump orders-new-record` — צילום של המסך במצב החדש
6. לחזור על 3–5 בתוך מסך שורות ההזמנה
7. `dump orders-search` אחרי שחיפשת אסמכתא ידנית — זה מה שיזין את בדיקת
   הכפילויות

### מה נכתב

```
discovery-out/2026-09-19_143022/
├── 01-orders-empty/
│   ├── report.md           ← להתחיל מכאן
│   ├── config-draft.yaml   ← YAML תקין עם הסלקטורים שאומתו
│   ├── elements.json       ← הכל, לעיבוד
│   ├── screenshot.png
│   └── html/               ← ה-HTML הגולמי של כל frame
├── picks-<זמן>.json
└── diff-<זמן>.json
```

`report.md` נפתח בסעיף **"Answers to the open questions"** שעונה ישירות:
האם המסך בתוך iframe ובאיזה, האם השורות הן טבלה או טופס, ואילו כפתורי
פעולה ושדות נמצאו.

### על הסלקטורים

כל סלקטור בדוח **נבדק מול העמוד החי** ומופיע רק אם הוא מתאים בדיוק לאלמנט
אחד. מה שלא נמצא נכתב `FILL_ME` — לא ניחוש. סדר העדיפות: `#id` → `[name]` →
`data-*` → `aria-label` → `title` → טקסט → נתיב CSS.

אם ה-id-ים ב-Priority נראים מיוצרים אוטומטית (מספרים ארוכים, GUID) — תגיד לי,
ונעדיף `[name]` או עוגן טקסטואלי.

## פרטיות

זו מערכת פרודקשן עם נתוני לקוחות אמיתיים, אז ברירות המחדל שמרניות:

* ערכי שדות **לא** נשמרים בדאמפים. `--capture-values` מפעיל את זה במפורש.
* גופי בקשות XHR **לא** נשמרים. `--capture-payloads` מפעיל במפורש.
* הקלדות **לא** מוקלטות. ה-recorder שומר רק מקשים עם מודיפייר (Ctrl/Alt) ומקשים
  מיוחדים (F1–F12, Enter, Esc, חיצים) — כלומר קיצורי דרך, לא תוכן.
* `storage_state.json` ו-`session-info.json` מכילים session חי ונמצאים
  ב-`.gitignore`. אל תשלח אותם.

⚠ **לפני ששולח לי קבצים מ-`discovery-out/`**: ה-HTML הגולמי וצילומי המסך
מכילים את הנתונים שהיו על המסך. הכי בטוח לעמוד על מסך ריק/חדש כשמצלמים, או
לשלוח רק את `report.md` ואת `config-draft.yaml`.

## למה לא `playwright codegen`

`codegen` עדיין שימושי ואפשר להריץ אותו במקביל:

```bat
playwright codegen --load-storage=storage_state.json https://your-priority-host/...
```

אבל הוא נותן סקריפט של פעולות, לא תמונה של המסך. הוא לא אומר לך באיזה frame
הדברים יושבים, לא בודק שהסלקטור ייחודי, לא מראה מה קרה ל-DOM אחרי לחיצה, ולא
מוציא קונפיג. בעיקר — `codegen` מקליט גם *פעולות כתיבה*, והכלי הזה לא מסוגל
לכתוב בכלל.
